# ChipMate Codex Compaction Parity Matrix

## 背景与结论

本文档单独审计 ChipMate 与 Codex 在上下文压缩机制上的差距，只覆盖 compaction，不替代 `chipmate-codex-context-parity-matrix.md`。

这里的 parity 目标是公开可见行为的工程等价：长会话接近上下文窗口时，系统应能触发 compact、生成或安装压缩后的上下文、保留近期用户意图、替换模型可见历史、持久化 rewrite metadata，并在中断或重启后继续恢复任务状态。本文不声称复制 Codex 私有内部机制，只对照公开源码中可观察的机制形态。

当前结论：ChipMate 的 Codex-style replacement-history compaction 主链路已达到基本 parity。当前实现已经具备 context window resolver、request-stage token gate、E1 `ContextWindowState` pressure check、compact candidate、persistent `context_compaction` event、model-generated completed / failed compact event、completed-event replacement history adapter、E2 current-turn inline re-pack、E3 compact-first / prune-fallback 合并、E4 高优先级 state snapshot、E5 redundant compact skip、E6 during-compact overflow retry、F1-F4 initial context reinjection / resume、G1-G2 service-only manual compact、G3-G4 mid-turn tool-loop safe-boundary compact / reinjection、H1-H3 Context Summary compact status / telemetry / long-thread warning、compact telemetry log、D5 rolling memory 边界保护、D6 compact strategy router，以及 H4/H5 DirectAgent 30+ turn parity eval 和矩阵回填。仍未完成的是用户可见 manual command surface、真实 VS Code UI smoke、provider capability 自动 token-budget path 和更细粒度 world diff；这些不阻碍 replacement-history compaction 主链路回填 Score 4。

## Codex 公开源码审计锚点

- `compact.rs`：Codex 的本地模型摘要 compaction 包含 auto/manual trigger、compact prompt、pre/post compact hooks、`ContextCompactionItem` lifecycle、replacement history、initial context reinjection、during-compact overflow trimming、analytics 和 compact 后 long-thread warning。
- `compact_token_budget.rs`：Codex 还有 token-budget compaction 路径，不生成模型摘要，而是安装 fresh context window；它仍走同一类 compact lifecycle、hooks 和 `ContextCompactionItem`。
- `session/context_window.rs`：Codex 的压力检测不只是总 token ratio，还区分 active context、auto-compact scope、full context window、tokens until compaction、prefill tokens 和 hard limit flags。
- `context_manager/history.rs`：Codex 的 history manager 维护 `history_version`、`reference_context_item`、`world_state_baseline`、replace/rollback 语义，以及 prompt 前的 history normalization。

## 评分标准

| Score | 含义 |
| --- | --- |
| 0 | 不存在 |
| 1 | 仅检测或日志 |
| 2 | 有 scaffold / metadata，但不替换真实历史 |
| 3 | 真实 compact 生效，但恢复、持久化或边界不完整 |
| 4 | 基本 Codex-style parity |

## 当前已具备

- `context-window` resolver：支持手动 context length、provider metadata、内置表和 `262144` fallback。
- E1 `ContextWindowState` pressure check：记录 active/prefill/body/scope tokens、threshold、tokens until compaction、hard limit 和 request-stage truncation，并用 `body_after_prefill` scope 避免 large prefill 误触发 soft compact。
- request-stage token gate：最终发送前可按 token/window 裁剪低优先级上下文。
- compact candidate：达到 soft threshold 或 request-stage truncation 后可生成 `CompactionState`。
- replacement history scaffold：可构造 retained recent user messages 与 `compaction_summary` item。
- `context_compaction` event v1/D6/H1 基础：schema、append-only helper、latest event 读取、rewrite metadata、request-stage `fallback_pruned` JSONL 写入、soft-threshold model-generated completed / failed event 写入、token-budget completed event 形态，以及 Context Summary latest event 回放。
- `context_compaction_lifecycle` v4 基础：started/completed/failed/interrupted lifecycle event helper，model-generated、token-budget 和 fallback path 可写入 lifecycle JSONL。
- compact hook v1 基础：DirectAgent fallback compact path 已接 pre/post hook，hook 支持 continue/stopped/error。
- compact event telemetry v1 基础：persistent event formatter 覆盖 completed/failed/interrupted/fallback_pruned。
- completed compact event adapter v2 基础：可将 latest completed replacement history 转为 provider-safe user/assistant history，并在 DirectAgent history path 中优先使用；E2E request snapshot 已验证 raw recent history 被替换。
- retained user message token-cap v2 基础：candidate replacement history 按 token cap 和 max count 保留近期 user intent。
- compacted transcript normalization v2 基础：adapter snapshot 会跳过重复 summary/item、orphan tool output、unsupported modality，并把 system role 转为 provider-safe continuity context；DirectAgent 会记录 diagnostics。
- compact summary prompt D1 基础：bounded prompt contract 覆盖 transcript slice、TaskState、PlanState、FileState、VerificationState、FailureState、EvidenceState 和 VisualEvidence fallback，并支持 prompt override。
- model-generated compact summary D4 基础：DirectAgent 可发起非 streaming、无 tools compact request，解析 JSON/文本输出，并在 summary quality gate 通过后生成 completed replacement history event；失败时写 failed compact event 并继续当前请求。
- rolling memory boundary D5 基础：rolling memory 仍只是 sidecar / compact 输入；只有 `status=completed` 的 `context_compaction` event 能驱动 replacement history adapter。
- compact strategy router D6 基础：`local_summary`、`token_budget`、`fallback_pruned` 由同一决策函数输出，DirectAgent 按 decision 分派并记录 strategy 日志。
- pre-turn inline re-pack E2 基础：completed `local_summary` / `token_budget` compact event 写入后会重新读取 session events、复用 completed compact adapter、重建本轮请求，并输出 `[context-compact-inline]` 日志。
- compact-first / prune-fallback E3 基础：request-stage truncation 先作为 compact pressure，completed compact 优先；只有 compact 未完成时才安装 pruned messages 和 `fallback_pruned` event。
- high-priority state snapshot E4 基础：completed replacement history 强制包含 TaskState、PlanState、FailureState、VerificationState、FileState 和用户纠偏，token-budget compact 也保留该 snapshot。
- redundant compact skip E5 基础：latest completed compact 已覆盖当前 historyVersion + 1 且 soft pressure 未增长时跳过重复 compact，并输出 `[context-compact-skip]`；hard limit / request-stage truncation 不跳过。
- during-compact overflow retry E6 基础：compact summary request 遇到 context-window overflow 时裁掉最老 compact prompt transcript message 并重试，成功后写 completed event 和 degraded reason。
- initial context reinjection / resume F1-F4 基础：completed compact event 记录 reinject mode 和 baseline metadata；后续请求注入 `<chipmate-initial-context-reinjection>`；simulated restart 可恢复 compacted transcript；settings/RAG/git/model 变化会标记 baseline invalidation reason。
- mid-turn compact G3/G4 基础：tool-loop 在完整 tool call/output 边界可写 completed compact event，并用 replacement history、`<chipmate-mid-turn-context-reinjection>` 与原始 tool suffix 重组下一次 provider request。
- Context Summary H1-H3 基础：用户可见 latest compact status、strategy、summary age、retained/omitted、fallback/failure reason 和 compact 后 long-thread warning。
- H4/H5 parity eval 基础：DirectAgent 30+ turn fixture 覆盖 pre-turn soft compact、model-generated completed event、replacement history、append-only session log、restart resume、rollback marker、stale evidence、visual fallback artifact path/sourceHash/page、PNG data URI 不进 provider request，以及 provider wire request 只有首条 system。
- compact telemetry log：可记录 trigger、before/after tokens、retained count、omitted count 和 reinject mode。

## 当前未具备

- token-budget strategy 的真实 provider capability 自动触发。
- `ContextCompaction` lifecycle 的 UI run-progress 展示。
- 更细粒度 initial-context / RAG / tool / world baseline prefill 分类与持久化 pressure event。
- compact prompt override；manual compact 和 mid-turn compact 已复用 hook 边界。
- manual compact 的用户可见按钮/命令入口。
- 真实 VS Code UI smoke、更多 provider 错误样本和更细粒度 world diff / RAG index hash invalidation。

## 推荐优先级

1. 优先补用户可见 manual compact button / command surface，复用现有 `compactSession()` pipeline。
2. 再补真实 VS Code UI smoke，验证 Context Summary compact status / warning / fallback reason 在实际 webview 中显示。
3. 然后补更细粒度 scope / prefill 分类，以及真实 provider capability 驱动 token-budget path。
4. 最后持续扩展 parity eval 到更多多工具、provider 错误样本和真实 RAG index invalidation。

## Assumptions

- 本文档只审计 compaction，不替代总 context parity matrix。
- 当前 compaction 能力评分保守处理：scaffold / telemetry 项最多 Score 2；只有 H4 这类 request 级 replacement-history / resume / stale evidence / visual fallback eval 证明的 capability 才能回填 Score 4。
- 原始 session JSONL 应保持 append-only；compact 和 rollback 只能新增可审计 rewrite metadata，不能删除原始 message。
- 文档中的 Codex baseline 来自公开源码中的可观察机制，不代表私有服务端实现细节。
- 本文档不写入任何私有 provider endpoint、私有模型名或 VSIX 注入默认值。
