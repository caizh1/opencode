# 01 Core Principles

## 1. 源码事实优先

本 skill 的目标是基于当前源码重新生成详细设计，不是润色、扩写或复述旧文档。

事实优先级如下：

1. 当前源码函数实现；
2. 当前头文件接口定义；
3. 当前结构体、枚举、宏、全局变量；
4. 当前调用链、引用关系、状态流转；
5. 当前构建脚本、模块注册和初始化路径；
6. 当前测试用例、日志、运行配置；
7. 旧详细设计文档。

旧文档只能用于模块定位线索、格式参考、差异对比、功能点覆盖对比，不得作为当前源码事实。

## 2. 正文禁止表达

新详设正文禁止出现：

- 根据原文档……
- 原文档指出……
- 基于原文档和源码分析……
- 结合原文档可知……
- 原文档第 x.x 节说明……

正确写法：

- 根据 `xxx.c::xxx_init()` 的实现可知……
- 从 `xxx.h::XXX_CTX` 的字段读写关系可以看出……
- 当前源码中 `func_a() -> func_b() -> func_c()` 构成主处理链路……
- 源码中未确认该行为，因此只进入差异报告。

## 3. 结论置信度

每条关键结论必须标记为：

- 已源码确认：有精确源码位置、结构体/宏/函数或控制流证据；
- 高置信推断：多个源码证据共同支持，但缺少直接注释或单点明示；
- 中置信推断：源码上下文支持，但仍存在不确定边界；
- 低置信待确认：只有弱线索，不得进入正文确定结论；
- 源码未确认：只能进入差异报告或待确认清单。

低置信和源码未确认不得进入新详设正文。

## 4. 证据最小要求

| 结论类型 | 最小证据 | 深度证据 |
|---|---|---|
| 模块职责 | 入口函数 + 调用链或核心结构体 | 入口函数内部控制流和上下游依赖 |
| 接口说明 | 函数定义或头文件声明 | 参数校验、错误分支、下游调用 |
| 数据结构 | 结构体定义 + 字段读写位置 | 字段在关键函数中的变更时序 |
| 状态机 | 状态枚举/宏 + 状态判断/赋值 | 状态变更触发链路和 guard 条件 |
| 异常处理 | 错误码/返回值 + 分支处理位置 | 完整错误恢复/清理路径 |
| 性能关注点 | 循环、队列、锁、缓存、批处理 | 热路径函数级分析 |

## 5. 防跳阶段原则

如果当前 session 因上下文、steps、时间或模型能力不足无法继续，必须保存断点：

- 当前 work package 标记为 INCOMPLETE；
- 更新 `resume-state.md`；
- 更新 `continue-prompt.md`；
- 更新质量门禁报告；
- 明确下一 session 的第一步。

禁止“由于篇幅限制直接生成最终 Word 输入”。
